# 迭代 1.1.1 设计：容器升级分步引导 + 运行日志落盘

日期：2026-11-01　分支：`feat/iter-1.1.1`　目标版本：**1.1.1**（patch，不跳 1.2.0）
关联：v1.1.0 已发布；本规格源于用户对设置页一句术语提示的反馈。

## 0. 要解决的问题

1. 设置页在容器环境下只说「检测到运行在容器中：容器内替换的二进制会在镜像重建时丢失，请改用新的镜像包再重建容器」。用户不熟 Docker，看到这句话**不知道下一步敲什么**。要改成能照着抄、一步一步做完就升级成功的引导。
2. 面板运行日志只在容器标准输出里，落在 OrbStack 虚拟机内部（`/var/lib/docker/containers/<id>/…-json.log`），用户的统一目录 `/Volumes/MAC_U_202411/docker/frpc-mesh/` 下看不到日志文件。要和 data 一样挂一份到宿主机目录。

## 1. 已核实的前提（不要重新假设）

- **Docker 配置层做不到日志落盘**：`--log-opt path=…` 被守护进程拒绝，实测报 `unknown log opt 'path' for json-file log driver`。所以第 2 件事**必须改程序**。
- **容器内看不到宿主机路径**：OrbStack 下 `/proc/mounts` 只给 `mac /data virtiofs`。因此引导里凡是要用户填自己路径的地方，一律改成**在宿主机执行 `docker inspect` 抄出来**，实测输出 `/Volumes/MAC_U_202411/docker/frpc-mesh/data:/data`。
- **镜像包只发 linux/arm64**：amd64 容器不能给下载链接，只能给源码构建指引。
- 生产容器 compose 的 `working_dir` 就是本仓库目录，镜像名 `frpc-mesh:latest`，容器名 `frpc-mesh`。
- 程序现在用标准库 `log` 写 stdout，没有任何文件日志；每台服务器的 frpc 输出只在内存环形缓冲里。

## 2. 功能一：`upgrade.guide` 分步引导

### 2.1 后端数据结构

`/api/update/status` 与 `POST /api/update/check` 响应的 `upgrade` 对象内新增 `guide`（不新增路由）：

```go
type GuideLink struct {
    Label string `json:"label"`
    URL   string `json:"url"`
}

type GuideStep struct {
    Title    string     `json:"title"`
    Desc     string     `json:"desc,omitempty"`
    Commands []string   `json:"commands,omitempty"`
    Link     *GuideLink `json:"link,omitempty"`
    Optional bool       `json:"optional,omitempty"` // true=可跳过
}

type UpgradeGuide struct {
    Kind     string    `json:"kind"` // docker_image | source_build
    Intro    string    `json:"intro"`
    Steps    []GuideStep `json:"steps"`
    Fallback GuideStep   `json:"fallback"` // 前端折叠展示
    Note     string      `json:"note"`
}
```

`Capability` 增加字段 `Guide *UpgradeGuide \`json:"guide,omitempty"\``。

### 2.2 生成条件与规则

- 仅当 `mode == container` 且 `Info.Latest` 非空且**通过 `x.y.z` 校验**时生成；否则 `Guide` 为 nil（前端不渲染入口）。校验复用 `internal/update` 已有的版本号解析，**不引入对 `internal/runner` 的依赖**（避免 update→runner 的反向耦合）。
- `Latest` 不合法时**直接不生成**（不做转义、不做清洗）：它来自 GitHub Release tag 且会被拼进可复制命令，宁可没有引导也不能给出可疑命令。
- `Kind`：`runtime.GOARCH == "arm64"` → `docker_image`；其他 → `source_build`。
- 包名与直链按 `Latest` 拼：`frpc-mesh-v<latest>-docker-linux-arm64.tar.gz`、`https://github.com/busfly/frpc-mesh/releases/download/v<latest>/<asset>`。
- 引导文案与命令模板作为常量放在 `internal/update/guide.go`，只有版本号/包名是变量。

### 2.3 步骤内容（arm64，`docker_image`）

`Intro`：「升级要换一次镜像并重建容器，全程在**你自己的电脑终端**里执行几条命令，约 2 分钟；期间隧道会断几秒后自动恢复。本页面不能替你执行，只能把命令给你抄。」

| # | Title | 内容要点 |
|---|---|---|
| ⓪ | （可选）先导出备份 | `Optional=true`；Desc「配置本来就在宿主机目录里，重建不会动它；想更保险可以先存一份 JSON」；`Link{label:"去导出备份", url:""}`（url 为空表示前端滚动到本页备份卡片，不跳外站） |
| ① | 下载新镜像包 | `Link` 指向直链；Desc「约 16MB，下载后**不用解压**」 |
| ② | 在宿主机终端导入镜像 | `cd ~/Downloads`（浏览器下载目录不是默认值时改成自己的）；`gunzip -c <asset> \| docker load` |
| ③ | 重建容器（二选一） | Desc 给判断方法「你放 frpc-mesh 的文件夹里有 `docker-compose.yml` 就用左边，没有就用右边」；左：`cd <你放 docker-compose.yml 的目录>`、`docker compose up -d --force-recreate`；右：`docker inspect frpc-mesh --format '{{ range .Mounts }}-v {{ .Source }}:{{ .Destination }} {{ end }}'`、`docker rm -f frpc-mesh`、`docker run -d --name frpc-mesh --restart unless-stopped --add-host host.docker.internal:host-gateway -p 18080:18080 -v <上一步抄到的路径>:/data frpc-mesh:latest` |
| ④ | 回页面确认 | Desc「等 10 秒刷新本页面，顶栏版本变成 v`<latest>` 就成功了」 |

`Note`：「数据都在宿主机目录里，重建容器不会丢；隧道会中断几秒后自动恢复。」

`Fallback`（默认折叠）：Title「万一升级失败或页面打不开怎么办」；Commands `docker logs --tail 100 frpc-mesh`；Desc 说明「容器起不来也不会吃掉配置，数据在宿主机目录；要退回旧版本，重新下载旧版本镜像包 load 回来再走一次第 ③ 步」。

`Intro` 末尾追加一句：「命令里的容器名 `frpc-mesh` 按你自己的改；不确定就先执行 `docker ps` 看 NAME 列。」

### 2.4 `source_build`（非 arm64）

不给下载链接。Steps：① `cd <你放 frpc-mesh 源码的目录>` + `git pull`；② `docker compose up -d --build --force-recreate`；③ 回页面确认。`Intro` 说明「当前版本没有发布本平台的 Docker 镜像包，请用源码构建」。

## 3. 功能二：`--log-dir` 运行日志落盘

### 3.1 参数与默认行为

- 新增 `--log-dir <路径>` 与环境变量 `FRPC_MESH_LOG_DIR`（命令行优先）。
- **两者都不设置时行为与现在完全一致**：只写 stdout，不创建任何文件。现有二进制与容器部署零影响。
- 设置时：stdout 照旧写，同时双写到 `<log-dir>/frpc-mesh.log`。
- 目录不存在则创建（0o755）；创建或打开失败时**只打印警告、不阻止启动**（日志写不了不该让面板起不来）。

### 3.2 滚动策略（固定，不加参数）

单文件 10MB，最多 5 份，滚动为 `frpc-mesh.log` → `frpc-mesh.log.1` … `.log.5`（超出删除最旧）。上限约 50MB。理由：NAS 上不能无限涨；再加两个可调参数属于过度设计。

### 3.3 实现边界

- 新增 `internal/logging/rotating.go`：一个实现 `io.Writer` 的大小滚动 writer（约 50 行，含单测），只依赖 `os`。
- `main.go` 里 `log.SetOutput(io.MultiWriter(os.Stdout, rot))`。
- **不改** runner 的 frpc 日志采集，**不做**每台服务器 frpc 输出落盘（本轮明确排除）。
- 容器以 `appuser`(uid 10001) 运行，宿主机 logs 目录必须可写：实现时在生产容器上实测，若写不进则在 `docs/deployment.md` 给一条 `chown`/`chmod` 命令，**不在程序里做 chmod**。

### 3.4 compose 与文档

- `docker-compose.yml`：`volumes` 增加 `- /Volumes/MAC_U_202411/docker/frpc-mesh/logs:/logs`（与 data 同风格注释说明），`environment` 增加 `- FRPC_MESH_LOG_DIR=/logs`。
- `docs/deployment.md`：运行参数表加 `--log-dir` / `FRPC_MESH_LOG_DIR`；挂载段落说明日志位置。
- `docs/operations.md`：第 1 节数据目录表加一行 logs；第 4.1 节容器升级改成「点页面里的『怎么升级？看步骤』照做」，保留手动命令作对照。
- `API.md`：`upgrade` 响应补 `guide` 结构与生成条件。

## 4. 前端

- `SettingsView.vue`：`capability.mode === 'container' && capability.guide` 时，在「容器运行」标签行末尾加轻量文字按钮 **「怎么升级？看步骤」**（字号/颜色按次要控件处理，不与「检查更新」主按钮抢）。
- 新增 `web/src/components/UpgradeGuide.vue`：卡片内**就地展开**（`v-if` + 局部状态，不新开路由、不用弹窗）。渲染 `intro` → 步骤列表（编号、标题、说明、命令行、可选标签、直链）→ `note` → 折叠面板放 `fallback`。
- 每条命令独占一行等宽字体 + 行尾复制图标。复制走 `navigator.clipboard.writeText`，**失败兜底** `document.execCommand('copy')`（面板常走 `http://内网IP`，非安全上下文 clipboard 会被拒）；再失败则选中该文本并提示「已选中，按 Ctrl/Cmd+C」。
- `commands` 中以 `#` 开头的行按「分组说明」渲染（次要字色、无复制按钮），用于分隔「用 compose」与「用 docker run」两套命令；用户整段复制到终端时 `#` 行本身也是合法 shell 注释，不会执行错东西。
- 回退指引用折叠面板，标题即 `fallback.title`，展开后只渲染它的说明与命令（标题不重复显示第二遍）。
- 展开状态不持久化：离开页面或刷新回到收起，避免卡片长期变高。
- 第 ⓪ 步的 `去导出备份` 用页内滚动定位到「备份与恢复」卡片（不跳外站）。
- `types.ts` 补 `UpgradeGuide`/`GuideStep`/`GuideLink` 类型；引导为空时不渲染入口，二进制运行也不渲染（那边本来就是一键升级）。

## 5. 错误处理与降级

- `guide` 缺失/为 null → 前端不显示入口，卡片保持现状（旧行为）。
- 后端生成 guide 时若 `Latest` 不合法 → `Guide=nil`，`reason` 保持现有那句术语提示（不空屏）。
- 日志目录不可写 → 启动时 stdout 打一条警告，面板正常运行，页面不新增错误状态。
- 滚动写入过程中出错 → 静默降级为只写 stdout（不能因为日志写不了影响主流程），并在 stdout 提示一次。

## 6. 测试

- Go 单测 `internal/update/guide_test.go`：
  - arm64 → `Kind=docker_image`，包名与直链含正确版本号，步骤含 `docker load`、`--force-recreate`、`docker inspect`；
  - amd64 → `Kind=source_build`，**不含任何下载链接**，含 `git pull` 与 `--build`；
  - `Latest` 非法（含空格/引号/空）→ `Guide=nil`；
  - `mode=binary`、无新版本、检查失败 → `Guide=nil`。
- Go 单测 `internal/logging/rotating_test.go`：写入超过 10MB 触发滚动、`.5` 之后最旧被丢、目录不存在时自动创建、目录不可写时返回错误但不 panic。
- 前端手测（生产容器 18080 就是活场景：容器运行 + 当前 1.0.1 + 最新 1.1.x）：展开引导、逐条复制（**必须用 `http://` 实测 clipboard 兜底**）、折叠回退、第 ⓪ 步滚动定位。
- 日志落盘真机验证：临时容器挂 `/tmp` 目录跑 `--log-dir`，确认文件生成、滚动生效、`docker logs` 仍同步可见；权限问题按 3.3 实测结论处理。
- 文档：`API.md` 的 guide 示例与实现一致；截图不引入真实配置（沿用演示环境）。

## 7. 发布与落地顺序

1. `feat/iter-1.1.1` 分支实现 → 互审 + 全量测试 → `make VERSION=1.1.1 release` 本地打包 → **等用户验收**。
2. 用户许可后才 push / PR / 合并 / tag `v1.1.1` / 上传 4 包 + `sha256sums.txt`。
3. 发布后才动用户机器：改 compose（logs 挂载 + 环境变量）→ 重建容器到 1.1.1 → 验证 `.../frpc-mesh/logs/frpc-mesh.log` 有内容、Mounts 显示两条。生产升级这一步**单独再确认**，因为它会中断隧道数秒。

## 8. 明确不做

- 不在页面里执行任何命令、不开远程执行接口。
- 不做 frpc 每实例日志落盘。
- 不为滚动加可调参数（大小/份数固定）。
- 不改 Docker 日志驱动配置（已证实不支持 path）。
- 不跳中间版本号。

# 迭代 1.1 设计：服务器级 frpc 版本、远程端口占用校验、开源仓库入口

- 日期：2026-10-31
- 对应 issue：#6
- 目标版本：v1.1.0
- 状态：用户睡前授权 Agent 按推荐方案自主落地（2026-10-31 深夜），设计审阅门由 Agent 自审替代

## 1. 范围

三个互不耦合的子功能，同一发布：

1. **服务器级 frpc 版本覆盖**：全局激活版本成为默认版本；每台 FRPS 服务器可单独指定版本。
2. **代理远程端口体验**：一键同本地端口、占用检测按钮、保存时自动校验一次、占用硬阻断。
3. **开源仓库入口**：WebUI 三处 + README 徽章与 Star 引导。

不在范围：frps dashboard API 集成（需新增凭据字段，已否掉）；udp 端口服务端探测（技术上不可靠，明示限制）；远程端口自动跟随本地端口输入（用户改为显式按钮）。

## 2. 服务器级 frpc 版本

### 2.1 数据模型

- `instances` 表新增列 `frpc_version TEXT NOT NULL DEFAULT ''`，空串=跟随默认。迁移沿用 `manage_port` 的套路：`pragma table_info` 循环里按列名判断后 `ALTER TABLE`。
- `model.Instance` 增加 `FrpcVersion string \`json:"frpc_version"\``；创建/更新/备份/恢复自动携带（`BackupInstance` 内嵌 `Instance`）。
- `model.Runtime` 增加 `FrpcVersion string \`json:"frpc_version"\``：该实例**当前进程实际使用**的版本，`Start` 时写入 proc，供列表显示真相。

### 2.2 版本解析

`Manager.ResolveFrpcFor(in *model.Instance) (path, effective string, err error)`：

1. `in.FrpcVersion != ""` 且 `HasVersion(pin)` → 用 pin；
2. 否则 `ActiveVersion()` 且已下载 → 用默认；
3. 否则沿用现有 `resolveFrpcBinary()` 的兜底（程序目录 `./frpc`、系统 PATH）。

`Start()` 改用它，并把 `effective` 记进 proc → `Runtime.FrpcVersion`。

### 2.3 显示口径（四处）

- 未运行：显示解析结果（pin 缺失时=默认版本）。
- 运行中：以 `Runtime.FrpcVersion` 为准。
- 文案：跟随默认→「默认 v{active}」；指定且生效=pin→「v{pin}」；指定但未生效→「v{pin} 未下载 · 暂用 v{effective}」（下载中同理，文案「下载中 · 暂用」）。
- 位置：`InstancesView` 表格新增「frpc 版本」列；`DashboardView` 服务器行版本小标签；`ProxiesView` 服务器 Tab 名后小字；`InstanceFormDrawer` 编辑时回显当前生效版本。

### 2.4 异步补下载与自动切换

- 触发点：进程启动 `StartEnabled()` 完成后跑一次 `reconcilePinnedVersions()`；创建/更新服务器保存后若 pin 未下载也调它。
- 行为：对每个 `enabled && pin != "" && !HasVersion(pin)` 且当前没有同版本下载任务的实例，复用现有异步下载（`StartDownload(pin, "github")`，内部已有镜像回退）；Manager 起一个 watcher goroutine 轮询 `DownloadStatus` 至终态：
  - 成功 → 对所有 pin==该版本且正在运行的实例 `Restart(id)`（隧道中断数秒自恢复，与现有重启语义一致）；
  - 失败（含版本已从远程消失）→ 不重试、不弹窗，保持默认版本，版本列按 2.3 标注；下次进程启动再 reconcile 一次。
- 可测试性：Manager 增加可注入的 `downloadFunc` / `restartFunc`（同 `update` 包 `execFunc` 的套路），单测不碰真实网络与进程。
- `DeleteVersion` 语义不变（仅禁删 active）；被 pin 的版本删除后该服务器回默认并标注。
- `ActivateVersion`（改默认）沿用现有 `RestartAllRunning()`：跟随默认的服务器立即切换，指定版本的服务器不受影响。

### 2.5 表单

`InstanceFormDrawer` 新增「frpc 版本」选择器：选项=「跟随默认（当前 v{active}）」+ 本地已下载版本列表。要指定未下载的版本需先在「frpc 版本管理」下载（显式一步，避免隐式联网）。编辑时若 pin 未下载，选择器仍显示该值并标注「未下载」。

## 3. 远程端口占用校验

### 3.1 后端接口

`POST /api/proxies/check-port`，body `{instance_id, type, remote_port, exclude_proxy_id}` →
`{state: "free" | "occupied" | "unknown", holder: string, note: string}`。

判定顺序：

1. **本机查重**：所有与目标实例同 `server_addr+server_port` 的实例下，`enabled` 且 `type ∈ {tcp,udp}` 且 `remote_port` 相同且 `id != exclude_proxy_id` 的代理 → `occupied`，holder=「服务器「X」的代理「Y」」。
2. **tcp 探测**：对 `server_addr:remote_port` 发起 2 秒 TCP 连接（复用现有 dial 工具）：
   - 连得上 → 若本机查重（**含**被排除 id 再查一次）发现唯一持有者是被排除的那条代理、且该代理所属实例**正在运行**（才可能真的占着端口）→ 视为自身 → `free`；否则 `occupied`，holder=「服务端已有监听（非本机配置）」；
   - 拒绝 → `free`；
   - 超时/其它错误 → `unknown`，note 说明「连接超时：可能被安全组静默丢弃或服务不可达；未阻断保存」。
3. **udp**：不探测。查重未命中 → `unknown`，note=「udp 端口无法从本机探测，仅确认本机其它代理未占用」。

`unknown` 永不阻断保存。

### 3.2 保存兜底

后端创建/更新代理时做一次本机查重（不含探测，零网络依赖）：同服务器、启用、tcp/udp、远程端口相同、排除自身 → 400「远程端口已被代理「Y」占用」。任何客户端都绕不过。

### 3.3 前端交互（ProxyFormDialog，仅 tcp/udp 显示远程端口行）

- 远程端口输入框后两个按钮：
  - 「同本地端口」：把 `local_port` 填入 `remote_port`；本地端口为空或非法时禁用。
  - 「检测」：调 check-port（编辑时带 `exclude_proxy_id`=当前代理 id），loading 态；结果以输入框右侧小标签展示：空闲=success、占用=danger+holder、无法判定=info+note。
- 「保存并应用」：`type ∈ {tcp,udp}` 且 `remote_port > 0` 且（本次弹窗内未检测过，或检测后 `remote_port`/服务器变更）→ 先调 check-port；`occupied` → 不保存、远程端口标红、提示 holder 并聚焦该字段；`free`/`unknown` → 继续保存。检测成功结果在参数未变时可复用，不重复请求。

## 4. 开源仓库入口

仓库地址常量集中一处（前端 `web/src/api/types.ts` 或常量文件），避免散落：`https://github.com/busfly/frpc-mesh`。

- **顶栏右上**：octocat 图标按钮（内联 SVG，与版本徽章并排、用户菜单之前），`target="_blank" rel="noopener noreferrer"` 直链仓库主页。登录后所有页面可见。
- **登录页页脚**：一行「v{version} · GitHub · 更新日志」，未登录访客与截图也看得到仓库。
- **设置页「关于」卡片**：补四条链接——开源仓库 / 提 Issue 反馈（`/issues/new`）/ Release 更新日志（`/releases`）/ 一句 Star 引导文案「觉得有用？去 GitHub 给个 Star，帮助更多人发现它」。引导话只在这里出现一次。
- **README.md / README-CN.md**：顶部三枚 shields 徽章（stars / latest release / license）；文末加一段 Star 引导（含 star 链接）。
- 「检查新版本」卡片不再加链接（版本说明弹窗已有「在 GitHub 查看」，避免重复）。

## 5. 错误处理与降级

- 探测 DNS 失败/网络不通 → `unknown`，保存不被卡死。
- 补下载失败不弹窗骚扰，仅版本列标注；每次进程启动 reconcile 一次，不做后台重试循环。
- 自动重启切换失败 → 走现有 `runtime.last_error` 展示，不回滚版本字段。
- 老备份文件（无 `frpc_version`）恢复 → 空串=跟随默认，天然兼容。

## 6. 测试

- Go 单测：
  - `ResolveFrpcFor` 优先级（pin 已下载 > 默认 > 兜底）与 pin 缺失回落；
  - reconcile 触发下载、下载成功后对运行中实例调用 restart（注入 fake）；版本不存在时不 restart；
  - check-port 三态：查重命中、探测连上（含自身排除）、拒绝、超时、udp 未命中；
  - 保存兜底查重返回 400、排除自身与禁用代理；
  - 迁移幂等（重复 Open 不报错）。
- 前端：演示实例（全假数据）手测——指定版本缺失→默认启动→补下载→自动切换；检测按钮三态；保存阻断；四处版本显示；GitHub 入口三处。按惯例更新 `docs/screenshots/` 受影响截图（instances / proxies / settings / login）。
